Theming

One generic tokens.scss file — Material 3 color roles plus density. Widgets reuse those tokens; you do not add --el-button-* aliases to the theme package.

Add theme files to your project: npx @ng-elemental/cli add theme

Open Theme in the sidebar to try BRAND colors on every component page. Apply keeps the palette for this session. Copy a :root snippet and paste it after @use of tokens.scss in your app.

Setup

The theme package copies tokens.scss and optional ElThemeService into your components directory. Import tokens once in your global styles so every component receives default values:

Components reference tokens with var(--el-…). As long as tokens are loaded, styling stays consistent and overridable.

Edit the BRAND block

Open the copied tokens.scss and change the BRAND section. Pair each role as light-dark(light, dark). Changing --el-color-primary once updates buttons, chips, checkboxes, sliders, and other widgets in both modes.

npx @ng-elemental/cli add theme --force overwrites this file — back up brand edits first.

Light and dark

Color pairs use CSS light-dark(). Dark mode flips when color-scheme is dark — set by ElThemeService.setMode('dark'), provideElTheme with mode: 'dark', or data-el-theme="dark" on <html>. TypeScript only toggles the mode; it does not hold a color map.

Color tokens

Edit BRAND values in tokens.scss for global changes. Derived tokens (--el-color-primary-hover, --el-color-hover, --el-color-disabled) are color-mix from those roles.

Density tokens

Spacing, radius, shadow, border width, icon size, and fonts. Unique widget sizes (chip height, slider thumb, avatar diameter) stay in that widget’s SCSS and copy only with that component.
