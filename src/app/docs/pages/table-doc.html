Table

Data table that always renders from data plus el-table-column children. Cells stringify row[name] unless a column provides elTableCell. You sort and page the array; the table does not. Pair with Pagination in the footer.

Usage

Pass the visible rows in [data]. Declare columns with name (the field key) and optional label. Add <ng-template elTableCell let-row> only on columns that need a widget. Header templates use elTableHeader. Project <el-pagination> as a child for the footer.

String fallback

No cell templates. Each body cell is String(row[name]). null and undefined render as empty — screen readers announce the column header for context.

Sort (you reorder data)

Name

Sort buttons expose aria-sort on the active column. The table only updates the model — you reorder data so assistive tech sees the new row order in the DOM.

Pagination footer

Pagination lives in the table footer landmark. Pass the already-sliced page as [data] so row counts match what pagination announces.

Empty and loading

Empty and loading slots replace the body so users are not left with a silent blank grid. Loading exposes aria-busy on the table region.

Row selection recipe

Selection is parent-owned — the table has no built-in model. Give the select column an empty header or a visually hidden label so checkboxes are not orphaned.

Standards and checks

  • Native table semantics with <th scope="col"> headers.
  • Sort buttons expose aria-sort; expand toggles use aria-expanded.
  • Name the grid with caption or ariaLabel.
  • Empty and loading states replace body content — no silent blank tables.
