Badge

Compact, non-interactive count and status marks. Use notification overlay when wrapping an icon, avatar, or button (top-end). Use an inline count pill next to labels like “More filters”. Badges are not chips — use Chip for selectable or removable tags.

More filters

Wrap a child for the overlay recipe; omit children for the pill. Default colors follow the recipe (error for overlay, primary for pill) so notifications and meta counts stay distinct without extra props. Prefer an outline or secondary button when nesting a primary pill so the count keeps contrast. Put the count in the wrapped control’s name — the badge is not focusable.

Usage

Notification overlay

Wrap the element that has unread or pending state. The mark sits at top-end (top-right in LTR) with a surface ring so it reads on avatars and icon buttons. Include the count in the wrapped control’s ariaLabel or alt — focus lands on that control, not the badge.

Overlay defaults to the error color. The host is not focusable. Name the button, link, or avatar; visible “8” is a sibling, not the control’s name.

Count pill

Place a self-closing badge next to copy or inside a button. Default color is primary so it reads as meta, not an alarm. Still not a chip: no click, select, or remove. Projected children belong on the overlay recipe — variant="pill" keeps them in the flow instead of hiding them.

More filters

Prefer el-badge for filter counts. Use el-chip when the control must be selected or removed. A pill inside a button is part of that button’s name.

Overflow

Counts above max (default 99) render as 99+ (or your max with a plus). Zero stays hidden unless showZero.

Overflow keeps the indicator width stable for dense toolbars. Empty zero avoids noisy chrome when there is nothing to announce.

Dot

A presence mark with no visible text. Always pass ariaLabel — the indicator uses role="img" so the name is legal on a non-text graphic.

Color alone is not enough — the accessible name carries the meaning for screen readers. Without ariaLabel, a dot is hidden from assistive technology.

Colors

Override the recipe default with a semantic color.

Fills use theme tokens (--el-color-error, --el-color-on-error, and siblings) so dark mode stays in sync.

Size

Overlay marks stay compact. Pill md is the readable inline size; sm fits dense toolbars.

There is no lg — a large badge reads as a chip. Use el-chip when the mark must be a control.

Placement

Overlay corners use logical insets (top-end is top-right in LTR, top-left in RTL).

Placement is ignored on pills. The corner nudge flips with :dir(rtl) so the mark sits outside the anchor in both directions.

Long content

Long labels ellipsize visually. The full string stays in the DOM, so screen readers still get it — no title tooltip.

Prefer short counts or words like NEW. Pass ariaLabel only when the SR name should differ from the visible text.

Standards and checks

Badge is a display mark — layout-only unless you wrap an interactive control.

  • Standards used: native span host; no APG widget pattern. Dots follow the same naming approach as el-avatar (role="img" + name).
  • Why: the host is not a button. Overlay counts belong in the wrapped control’s name. Visible short text names standalone pills. CSS :has() picks overlay vs pill on first paint.
  • Native host; not focusable and not a live region.
  • Visible text names the indicator; dots need ariaLabel (as role="img").
  • Overlay on a control: put the count in that control’s ariaLabel / alt.
  • Color is never the only cue — pair with text or an accessible name.
  • Do not make the badge itself clickable — wrap with a link or button when needed.
  • Use el-chip for assist, filter, and removable tags.

References: A11Y Project Checklist, WCAG 2.2 (1.3.1, 1.4.3, 1.4.4), ARIA in HTML (naming a span), Material 3 Badge, Ant Design Badge, shadcn Badge.
